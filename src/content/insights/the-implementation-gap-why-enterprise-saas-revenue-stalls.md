A client signs an engagement and arrives at kickoff expecting the commitments made during the sales process to be understood. The delivery team needs that context before it can make a credible plan.

This is a workflow problem to inspect. It does not establish a universal go-live delay or a rule for when revenue may be recognized; finance owns the accounting determination.

## Define the package the receiving team needs

Record the client's stated objective, approved scope, named stakeholders, technical prerequisites, dependencies, and acceptance criteria. Keep a proposal, an executed agreement, and a conversation note distinct as sources.

The receiving owner should be able to see which commitment is agreed, which interpretation needs confirmation, and which prerequisite is still open.

## Extend the tools already in use

Check existing CRM, project, and document features before adding another workspace. A clear handoff template and owner may solve the first problem. Where context must cross systems, use a supported integration with explicit source and update rules.

A failed handoff should be visible. Duplicate triggers, missing records, and rejected updates need a recovery path rather than quiet retries that create inconsistent work.

## Use assistance to prepare, not approve

A model may propose a summary of permitted notes with source references. The delivery owner confirms it against the authoritative scope before it becomes a commitment or client message.

The reviewer checks the exact introduction, resolves missing context, and authorizes its use. Do not allow proposed prose to define delivery obligations or change workflow state on its own.

## Measure the handoff

Count missing prerequisites at kickoff, repeated requests for the same information, time waiting for an owner, and rework from misunderstood commitments. Distinguish a source problem from actual delivery capacity.
